## Decisions
- **Merge conflict resolution** (NavBar.tsx, App.tsx, App.css, Context.md conflicting between local work and the collaborator's `origin/main`): resolved by keeping both sides' additions side by side rather than picking one — e.g. `FiscalIndicators` renders alongside `HudCenterSwap` in the header (not replacing it), and NavBar's category list/render-dispatch got every entry from both branches merged together (Technology, Corporations, Stock Exchange, Debt, Construction, Trade, Demographics, Characters, Laws, etc.). The user then committed this merge themselves.
- **Top HUD resource bar narrowed**: per explicit request, `ResourceBar.tsx` now only shows Exotic Matter, Hyperium, and a renamed "Special" resource (was "Other") — via a new `HUD_RESOURCE_IDS` filter constant in `resourceData.ts`. The full resource catalog (energy/minerals/food/consumerGoods/alloys/exoticMatter/hyperium/special) and `resourceStore` are untouched — this only narrows what's *displayed* in the header, not the underlying data model.
- **Treasury/Balance made clickable**: `FiscalIndicators.tsx`'s two indicators were previously inert `<div>`s; they're now buttons that open a real info window using live `CountryFiscal` data (treasury/balance/debt/rating, revenue/expenditure breakdown) — same click-to-open-info pattern `ResourceBar` already used.
- **DraggableWindow maximize/restore**: implemented as an ordinary `pos`/`size` state change to a computed "fill the screen between the HUD bars" target (same mechanism drag/resize already use), NOT a separate CSS positioning scheme — this is what lets it animate smoothly. A transient `.animating` CSS class is armed via a `setTimeout`-deferred two-step sequence (arm the transition class first, apply the real value change one macrotask later) so the browser actually has something to interpolate from. Maximized windows span full width, covering the sidebars (same footprint as the tech-tree overlay). A `maximizable` prop (default `true`) lets specific windows opt out — set to `false` on the three top-bar popups (Treasury, Balance, the resource-info window) since "fill the screen" doesn't fit their glance-and-close purpose.
- **Gallery View — built, then simplified after live feedback.** First pass: a grid (up to 9 tiles) of live, independently-orbitable mini-scenes with per-tile click-to-select. User feedback: "too glitchy... don't make it navigatable, just make it a live view of the tabs, where clicking one switches to it. Remove the sidebars when in gallery view." Final, current design:
  - Each tile is a fixed-camera (no OrbitControls), click-through live scene — bodies/ships still animate, camera never moves, nothing in a tile is individually clickable.
  - The **entire tile is one `<button>`** — clicking anywhere in it (a planet, empty space, the header) switches to that tab and closes the grid. No separate per-body selection state exists anymore.
  - NavBar and Outliner (both sidebars) are unmounted entirely while gallery mode is active, since neither means anything about "the" active tab once 9 are shown at once.
  - Tiles read from each tab's own **stored `TabSnapshot`** (not the live global `viewStore`), reusing the same pure presentational scene pieces (`Sun`/`Planet`/`Moon`/`HologramBody`) the real scenes use — none of them mutate global state, which is what makes 9 simultaneous instances safe.
  - Real bug found and fixed: opening gallery wasn't capturing the *active* tab's live navigation into its own stored snapshot first (that only normally happens on `switchToTab`/`createTab`), so gallery would show stale data for whichever tab was active when opened. `setGalleryMode(true)` now captures it first.
  - Gallery toggle button lives in the tab strip, only appears once there are 2+ tabs, capped at 9 tiles (real WebGL-context-count ceiling, not a display choice).
- **Biology added to the Physics tech tree**: a new root branch (`biology` → `genetic-engineering` / `xenobiology`, costs 50/90/90, two non-converging children — same shape as the existing Quantum/Atomic branches) placed **deliberately before** Relativity/Quantum/Atomic/Extradimensional/Anomalous, right after Electromagnetism — per the user's explicit instruction that biology is a foundational science, not one of the advanced/theoretical branches. Root count is now 9 (8 open + locked Anomalous), updated in `tests/tech.test.ts`.
- **DraggableWindow mount-time clamp**: fixed a real bug where a window with unusually tall content (e.g. a long description) could open with its title bar — and close button — rendered above `y=0` in a short viewport, with no way to dismiss it. Added a `useLayoutEffect` that clamps the initial position into the viewport once, mirroring the existing drag-time clamp logic. No-op for every window that already fit (verified: this doesn't perturb any existing window's default position).
- **Pre-existing CSS bug found and fixed in passing**: `.econ-pos`/`.econ-neg` were defined *before* `.inspect-value` in `App.css`; at equal specificity, source order decided the tie, so `.inspect-value`'s plain white silently always won over the intended green/red — this was breaking color in `EconomyPanel.tsx` too, not just the new code touching it. Moved both rules after `.inspect-value`.

## Important Details
- **Sandbox quirks confirmed this session (real, not app bugs — verify around them, don't chase them as bugs):**
  - The Browser pane can be "hidden" from the harness's own perspective, which appears to suspend `requestAnimationFrame` callbacks indefinitely (confirmed empirically: a nested-rAF deferral never fired at all until switched to `setTimeout`, which fired reliably). Any code needing a guaranteed-eventual callback (e.g. arming a CSS transition before changing the animated property) should use `setTimeout`, not rAF, in this environment — real end users won't have this problem since their tab is actually focused.
  - `getComputedStyle`/`getBoundingClientRect` can also report stale/wrong values immediately after a change, even when the raw `style` DOM attribute is already correct. Verify via the attribute string directly, or take a screenshot (which seems to force a real paint) before re-measuring — a deeper version of the already-known "screenshots can go stale" issue.
  - Vite HMR in this dev setup intermittently triggers a full page reload back to the onboarding screen while testing (happened many times this session, unrelated to what was being tested). Not fixable from here — just expect it and redo test setup (reselect a country, recreate tabs) when it happens.
  - Dynamic `import()` calls used to probe stores from the browser sometimes throw "Promise was collected — the page navigated" even when the action actually succeeded. Re-check state directly afterward rather than trusting the error.
