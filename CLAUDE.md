# Terra Relicta: Conquest

Web grand-strategy game: Vite + React + TypeScript + three.js/r3f, zustand stores. Two-person team. The user here is mr1noobfatfish, the author of Complex economy mode (`src/economy/*`) — treat it as the user's own code.

## Standing rules
- **Never commit unless explicitly asked.**
- **Verification sweep after any change:** `npx tsc -b`, every `tests/*.test.ts` (`npx tsx tests/<name>.test.ts`), and `npm run build`. All must be clean.
- **Filesystem is case-insensitive.** `Context.md` (~330KB, git-tracked running log) is the same file as `CONTEXT.md`/`context.md` — never overwrite it or create a differently-cased "separate" file. `HANDOFF.md` is a separate, older handoff note (partly stale).
- Don't read `Context.md` whole — grep it for the section you need, or read with offset/limit.
- Dev server serves from `/TRCONQUEST/`. Onboarding gate: pick a nation first (`usePlayerStore.getState().selectCountry(id)`; ids: `imperial-state-of-mars`, `republic-of-venus`, `orion-republic`, `kingdom-of-lalande`).

## Verification conventions
- **Store-probe:** to test UI state fast, temporarily expose zustand stores on `window` from `src/main.tsx`, drive them via the browser JS tool, and **always revert `main.tsx`** before ending the turn.
- Browser pane can be "hidden" (rAF suspended, stale `getComputedStyle`); verify via DOM attributes / screenshots, and use `setTimeout` not rAF for guaranteed callbacks. Vite HMR sometimes reloads to the onboarding screen — just redo setup.
- Tests are plain `tsx` scripts with a local `check()` helper, not a framework. One file per feature area; add a test file for any new mechanic and regression tests for bugs found.

## Architecture notes
- Pure-function resolvers separate from store I/O (e.g. `stepEngagements` in `scene/combatResolution.ts` vs `hooks/useCombatResolver.ts`). Keep new logic pure and testable.
- Timers are absolute `simDays` deadlines, never countdowns.
- Data/balance constants live in `src/data/*` (`combatData.ts`, `shipModules.ts`, `techData.ts`, `commsData.ts`); state in `src/state/*`.
- Optional new fields on `ShipInstance`/`CombatParticipant` default via `??` so existing literals and tests don't need updating.
- Zustand selectors should return primitives (join ids into a string) to avoid re-render churn.
- **FTL comms** (`scene/commsVisual.ts`): simulation state is live truth, and every ship is DRAWN at its real position (`playerShipRenderPosition`); there is no "predicted" marker. Panels, health bars, status text and route lines are LIVE (the delayed `visualShipSnapshot` is no longer used by any view); what lags is signal time: orders and ship commands queue behind it (`queueMoveOrder`/`queueStance`, `scene/shipCommands.queueShipCommand`; fired by `hooks/useCommsResolver.ts`), and a fight is unknown until its news arrives (`engagementKnownToPlayer`: not in the battle list, no Enter Combat, no auto-pace to TAC). Delay is computed from the ship's *live* position (`playerCommsDelayToShip`), never stale `ship.location`. Combat arena stays live. Hyper Comms = zero delay everywhere.
- Combat tactics: boosts (thruster/shield/weapons) are mutually exclusive; Spin Thrust blocks Thruster Boost.
- **Nations own everything.** `ShipInstance.ownerId` (required) is a countryId; there are no ownerless ships and no stored allegiance. Hostility = `atWar(a, b)` from `state/diplomacyStore.ts`; the player-relative relation ('own'/'neutral'/'enemy') is derived via `state/shipRelations.ts`, never stored. Player controls gate on `isPlayerOwned`; `planMove` is player-gated, `planMoveUnchecked` is for AI/simulation.
- **Combat is N-sided:** one side per nation (`Engagement.nations`, player's nation = side 0); `CombatParticipant.hostileSides` is recomputed from diplomacy every `syncEngagements`; always test enemies with `isEnemy`, never `side !==`. Tests use `tests/testNations.ts` (TEST_PLAYER/TEST_ENEMY at war).
- **Per-country economy:** resources (`resourceStore.stateFor(id)`), shipyards (`shipyardStore.ordersFor(id)`), and tech are per nation; the player's view goes through `usePlayerResources`/`usePlayerTech`.
- **Territory** (`scene/territory.ts`, `state/territoryStore.ts`): per-body `bodyOwner` (changes only by treaty) and `bodyController` (occupation). A nation claims a system when it owns every *claimed* body there. `cedeBody` also moves the economy World (`economyStore.setWorldOwner`, the one sanctioned edit to collaborator code).
- **Armies** (`scene/armyLogic.ts` pure, `state/armyStore.ts`, `hooks/useGroundCombatResolver.ts`): armies are on a body, embarked on a `troop-transport`, or recruiting. Invading needs war with the controller + orbital superiority (no armed enemy ship orbiting); ground battles are derived, not stored, and step in fixed 0.25-day steps. Destroyed transports lose their cargo; blockaded worlds can't recruit.
- **Terrain battles** (`scene/terrainMap.ts` relief, `scene/terrainBattle.ts` sim, `scene/terrainWar.ts` orchestration, `state/terrainStore.ts`, `scene/TerrainViewScene.tsx`, view level `'terrain'`): when hostile line units (not artillery-only) come within `TERRAIN_TRIGGER_CELLS` (1.5, just outside the 1.0-cell contact range) `resolveGroundWar` lifts them (and units within 2.5 cells) into a `TerrainBattle`: the SAME war at finer resolution (same ranges/speeds/damage/entrenchment, in fine cells) on a relief grid (56x56 over 7 cells) with fine terrain under every unit, a height advantage (`HIGH_GROUND_BONUS`) and slope slowing. Engaged units are frozen in `stepGroundWar` (`GroundWorld.engagedUnitIds`, default undefined = old behaviour, so direct-`stepGroundWar` tests are untouched); their strength, position, route and `firingAtId` are written back to `armyStore` every resolve, so the ground map, panels, `playerFightLive` and pacing are unchanged (OPS pace, no new time mode). Ends when a side is gone or no hostile pair is within 3 cells for 2 days; survivors get `objectiveNode: null` so the coarse AI replans. Coarse orders to engaged units are refused (`armyStore.orderUnits`): the player orders them on the terrain map (`terrainStore.orderUnits/targetUnits/haltUnits`). Relief is a property of the ground (noise of the globe point), drawn as a glowing point cloud; the sim uses only the grid. Battles list as kind `'terrain'` (`battleList.playerTerrainBattles`, Outliner, badge, a chip on the ground map). No line-of-sight blocking yet.
- **War & peace** (`scene/warScore.ts` pure, `scene/peace.ts` store I/O): war score = occupied territory share (capital/world/outpost values) + capped battle balance; `evaluatePeace` is the one acceptance rule for AI and player alike. Start/end wars through `declareWarOn`/`proposePeace`/`makePeace`, not the raw store, so events and territory stay consistent.
- **Strategic AI** (`src/ai/`): per-empire blackboard built from one snapshot; six pure agents run in order — Diplomat → Strategist → Expander → Shipwright → Admiral → Marshal — returning intents; `executor.ts` is the only writer and uses the player's own store actions. Tuning in `data/aiData.ts`. Only nations in `countryRoster.STRATEGIC_AI_COUNTRY_IDS` run it (never the player's, never Lalande); AI wars only target neighbours (nations sharing a system). `tests/ai.test.ts` runs a headless campaign (`AI_TRACE=1` for a monthly trace).
- **Sandbox** (`scene/sandboxSetup.ts`, `components/SandboxPanel.tsx`): a main-menu mode with no nations. The player is the no-nation faction `SANDBOX_PLAYER_ID` (`playerStore.sandbox`), and the other three are `FRIENDLY_ROGUE_ID` / `NEUTRAL_ROGUE_ID` / `PIRATES_ID` in `countryRoster`, hostility fixed by `diplomacyStore.rogueHostility` (pirates fight everyone, the rest only pirates; nothing stored as a war). Territory starts unowned; the AI, starting forces and strategic resources are gated off on `sandbox`; nation-only UI (nav categories, fiscal/resource bars, action bar) is hidden.
- **Scenarios** (`data/scenarios.ts` ships, `data/armyScenarios.ts` armies, one loader `scene/scenarioLoader.ts` for both the Sandbox panel and the dev Debug Console): roles resolve to the player's nation vs another nation in a normal game, or player faction vs pirates in the sandbox. Army scenarios are field battles on unowned ground, anchored near real places (`battlefield.near`: Earth's Central European forest and the Congo basin, Pluto's far-side ice; `scene/armyScenario.ts` builds them); the ground war is deterministic, so `tests/armyScenarios.test.ts` proves each tier with one run per scripted plan (hold / bring up the reserve / fall back, link up and counter-attack). The ground AI has no key nodes on unowned ground, so only the scenario's enemy marches (an initial path) and sandbox armies otherwise hold and fire.
- **Comms & the arena:** FTL comms delay (`scene/commsVisual.ts`) governs orders given from OUTSIDE the combat arena; inside the arena the player has direct contact (`inDirectContact`, delay 0), so `CombatPanel` has no out-of-contact lockout. Ships AND armies are coloured by relation to the player (`state/shipRelations.relationColorOf`: green own, blue allied, yellow neutral, red hostile), never by nation; nation colours are for territory only. Never call a hook after an early `return` in a component (`tests/arenaContact.test.ts` scans for it — a ship destroyed mid-render used to blank the combat view). `DraggableWindow` keeps its title bar below the top HUD bar and grows downward when its content gets taller. It remembers the size the player drags it to for the game session only (`state/windowLayoutStore.ts`, in memory, reset by `resetGame`), keyed by `memoryKey` (default the title; windows titled after a specific thing pass a stable key, e.g. `"planet"`, `"ship"`).
- **Spaceports on the ground map** (`scene/spaceportSites.ts` pure, `data/bodyRotation.ts` real rotation periods): every spaceport a world's economy runs (`nationEconomy.spaceportSitesOf`, both modes) is a full key node: the terrain's own spaceport plus extra sites placed near the equator on fast spinners (by the cities on slow/locked worlds) and ~1 in 5 strategic outliers; each carries its operator. Use `defenseStore.groundKeySurface` (+ installations) / `groundPortSurface`, or the `useGroundKeySurface` hook, never the bare terrain surface, wherever key nodes matter (ground war, AI snapshot, planet screen, ground map).
- **Real maps** (`scripts/terrain/` build pipeline, never shipped → `src/data/bodyTopography.ts` per-node data + `public/maps/<body>.png` pictures; decoded and turned into terrain by `scene/bodyTopography.ts`): every solid solar-system body with data (NASA/USGS/NOAA DEMs and mosaics, IAU Gazetteer features). Earth = ETOPO 2022 bedrock with the sea +70 m (ice gone, connected sea only); Venus = sea covering Earth's 70.8% share (Earth's full volume would leave 2.3% land); Mars = Arabia shoreline −2,090 m. Haumea/Makemake/Eris/Deimos/Uranus's moons and other star systems stay procedural; unmapped parts of partly-seen bodies too. Real bodies keep their real seas (no mainland-growing loop); `BodySurface.reliefM` feeds the terrain-battle relief; the pictures (loaded per body on open, `scene/bodyPicture.ts`) give the globe/flat map/hologram real coasts and relief shading — looks only. Rerun the pipeline with `npx tsx scripts/terrain/build.ts [cacheDir]` (~260 MB of range-requested downloads the first time). A capital is its nation's biggest city (two urban rings); `Country.capitalCityName/capitalCityAt` name and place it (Mars: Akakyō in Xanthe Terra; Venus Paphos; Orion Elysion; Lalande Bellerive). Every key node is named from its FOUNDING nation's list (`data/cityNames.ts`: Mars = Chinese names in on'yomi with kanji, Venus = Greek/Aphrodite, Orion = mythic/utopian, Lalande = French) via `scene/keyNames.ts` (`keyNameOf`, `cityOfNode`, `KEY_ROLE`); real bodies also carry IAU region names per node (`bodyTopography.regionAt`). The Ground panel lists key nodes (click centres the camera: `groundViewStore.focusNode`); map markers show names. Planet-screen building grids have a session 'Group identical' toggle (`state/planetViewStore.ts`, `components/planet/grouping.ts`).
- **Key sites & Military district** (both modes): the buildings that ARE the ground war's key nodes come from `scene/keyBuildings.ts` (capital's landmarks in `data/landmarks.ts`); shown in a Civic card and the Defense tab, captured with their node, no slot. Fortress/shield/battery need a free Military district slot (`defenseStore.canBuildDefense`, `nationEconomy.militarySlotsOf`; `militarySlots` synced into both economies). A built `spaceport` installation becomes the world's spaceport key node if it has none (`defenseStore.liveGroundSurface`).
- **Exploration, survey, cargo & Starbases** (`scene/surveyLogic.ts` pure, `state/surveyStore.ts`, `hooks/useSurveyResolver.ts`, `scene/intel.ts`, `scene/cargoLogic.ts`, `scene/shipCommands.ts`, `state/starbaseStore.ts`): stars always draw, but a star's information (owner, borders, body list, Enter System) shows only once a **Science Ship** has explored it and the report reached the capital. The survey store has two layers per nation: `discovered` (truth; the AI and rules read it) and `known` (after signal delay; the player's UI reads it via `usePlayerIntel`). A nation always knows systems where it owns a body. Exploring and surveying are two independent ship commands (`explore`, `survey`), each needing only that the science ship is resting at the star (never the player's delayed knowledge, and surveying needs no exploring first); a `surveyJob` surveys one body per `SURVEY_DAYS_PER_BODY`. Right-clicking a star with a science/construction ship selected opens a menu (`scene/StarContextMenu.tsx`): at an unexplored star "Explore system" (flying there IS exploring; the intel comes on arrival) instead of "Move to", at an explored one "Move to"; plus Survey and Build Starbase (greyed out with the reason unless a selected Construction Ship could build there, `canBuildStarbase(..., {anywhere:true})`) — all fly there and act on arrival (`ShipInstance.arrivalCommand`, optionally to a `bodyName` for a refill; fired in `hooks/useShipOrderSettler.settleShips`; an order to another star cancels it). Borders and nation names need an explored system; a Starbase in an unexplored one is an unidentified grey diamond. A **Construction Ship** builds a Starbase only at a fully surveyed star, paid from the goods in its own hold (not consumed, so it builds again); a **Cargo Ship** hauls (`ShipClass.cargoCapacity`, `ShipInstance.cargo`, loaded at an owned body, transferred between ships resting in the same place). Construction Ships need Orbital Construction (`ShipClass.requiresTech`, enforced in `shipyardStore.queueBuild`). Player commands (survey/load/transfer/build) go through `queueShipCommand`; the AI calls `applyShipCommand` directly. The AI **Expander** (`ai/expander.ts`) researches the road to Orbital Construction (research income exists only in Simple mode, so in Complex an AI still explores and surveys but never builds), keeps a science/construction/cargo ship, surveys outward, and claims the nearest surveyed unclaimed star (any Starbase, even under construction, blocks a rival's target). Borders render as shader bubbles with seams and nation labels (`scene/TerritoryDiscs.tsx`).
- **Controls:** Esc opens the menu (`components/EscapeMenu.tsx`, `state/menuStore.ts`: pauses, resumes on close only if the menu paused it; holds Settings and Quit, which calls `scene/gameReset.resetGame` — every game store's `getInitialState()`, settings kept), Space pauses (`hooks/useKeyboardControls.ts`), WASD moves every scene's camera (`scene/KeyboardPan.tsx`: pan on the map views, orbit on globe/arena views; it turns lock-on off). Shift is the universal "queue" modifier (`scene/queueModifier.ts`, tracked globally because scene callbacks get no mouse event): ships queue `ShipInstance.orderQueue` (fleet-wide, dispatched by `scene/orderQueue.dispatchQueuedLegs` from the settler; a plain order replaces it), and behind comms delay each queued order is its own signal (`pendingQueueAdds`); arena ships queue `CombatParticipant.stops` (planned leg by leg, `advanceParticipantStops`, so `pruneOvershotWaypoints` can't skip them); ground units extend `unit.path` (`armyStore.orderUnits(..., queue)`). Signals in flight are drawn as dots crawling from the capital (`scene/CommsSignals.tsx`). Vite HMR does not re-run effects inside a r3f Canvas — reload the page after editing scene code before judging behaviour.
- **Economy modes** (`playerStore.economyModel`, picked at the main menu, fixed per game): `'complex'` = Complex mode (the collaborator's deep sim, `src/economy/*`, economyStore) and `'abstract'` = Simple mode (`src/economy-abstract/*` pure, `state/abstractEconomyStore.ts`, data in `data/simplisticEconomyData.ts`, UI `AbstractEconomyPanel`). Simple changes must never touch Complex mode. In Simple mode the goods stockpile IS resourceStore, a nation's economy runs on the bodies it owns and controls, and non-player nations are steered by `economy-abstract/abstractEconomyAI.ts` from `useEconomyTick`. Nations trade with each other in both modes, peace only: Complex `economy/internationalTrade.ts` (arbitrage, freight-capped, paid through FX, run after every nation's tick; pass `atWar` in `tickEconomy`'s options), Simple `economy-abstract/tradeMatching.ts` (standing orders fill from partners' exports/spare stock each month). Complex mode's stability rests on: wages as a labour share of value added earned (rigid downward), the fiscal rule (`Country.purchaseScale`), price-elastic demand, the seed covering bureaucracy and starting wages at the bargained level, and damped AI (divest a level at a time); `tests/complexStability.test.ts` guards it (5 yrs, AI on) — never re-add a sales/profit production throttle (it spirals). The start is calibrated to the sim's own equilibrium: the seed balancer sizes producers per NATION (worlds ship to each other) within each world's workforce, plants open at a staffable run with a month's stock, and `src/economy/seedCalibration.ts` (GENERATED by `npx tsx scripts/economy/calibrate.ts` — rerun after changing the seed or the tick) holds each world's settled prices/wages and each nation's starting tax rate. The AIs add capacity only for a good that's scarce (price ≥ base with under half a month unsold, OR buyers short in the world reports) with its inputs made in the nation (`economy/scarcity.ts`), never for a good already being built on that world; owners never retool into a glut. Spare capacity is MOTHBALLED, not closed: `Building.idle` (0–1) caps the run and the jobs; the seed balancer mothballs level-1 plants the nation doesn't need (never the `NEVER_MOTHBALLED` basics), idle capacity reopens 0.2/month while its good is scarce and supplied, and both AIs downsize via `economy/downsizing.ts` (a level, or more mothballing at the last one; never spaceports/seaports). Equipment inputs (tools/machinery kinds, `CAPITAL_INPUTS`) degrade output to a 0.6 floor instead of stopping it. The seed completes every nation's supply chains (`withSupplyChains`) and adds transport (`withTransport`: spaceports at 2 per billion people split between the state and the nation's operator company — Tenkū Kōro, Kypris Astroporia, Arcadian Starlines, Compagnie Stellaire — and a seaport on worlds with seas). Textiles (dyes, chemicals, livestock) are an everyday Clothing need; sulfur feeds chemicals/fertilizer/explosives; spaceports burn spaceships and rockets, seaports ocean-going ships. Shipping (domestic and international) targets NEXT month's need. Inflation is measured from prices (`monetaryPolicy`: monetary pressures act as a `priceDrift` on real prices; Taylor rule raises rates on a positive gap). Simple mode has spaceships and rockets (spaceyard, rocket works) and a slot-free `spaceport` building (`noSlot`): each level adds `TRADE_PER_SPACEPORT` of trade capacity (`AbstractReport.tradeCapacity`, slowed when short of rockets/spaceships) and `matchTrade` caps each nation's trade by it (no spaceport, no trade).
- **Tooltips & charts:** hover tooltips are global (`components/TooltipLayer.tsx`, mounted in `main.tsx`) — give any control a `title` and it gets a styled tooltip (the ONE tooltip system: the layer lifts EVERY title up the tree while hovered (`titledChain`, not just the nearest — else the browser falls back to an ancestor's plain tooltip a moment later) and re-lifts one a re-render puts back (MutationObserver); in SVG use `data-tooltip`, never a `<title>` child); add concept explanations to `data/glossary.ts` (short labels matching a term get them automatically, in both modes). History graphs use `components/TimeChart.tsx` (month x axis, value y axis, 6M/1Y/3Y) with `endTick` = the economy store's tick.
- **Time & interruptions:** three paces on one clock (`gameTimeStore`): STRAT 6 d/s, OPS 1 d/s (ground battles), TAC 1 s/s (ship combat), picked directly from three buttons. Fights the player is in auto-switch the pace only when they START (`useCombatResolver`, `useGroundCombatResolver.followGroundFightWithClock`), never while one is going on, so the player can always switch back. AI peace offers to the player pause the game (`confirmStore` `pausesGame`) and are throttled with a per-war cooldown that doubles on each decline (`ai/executor.mayOfferPeaceToPlayer`). The Outliner's Battles section (`scene/battleList.ts`, kept current in `state/battleStore.ts` by `hooks/useBattleTracker.ts`) lists every space and ground battle the player is in and opens it, and `components/BattleBadge.tsx` marks the same fights on every map level (body, star and neighbourhood markers). The pace only ever moves DOWN on its own (`hooks/fightPace.ts`): a ground fight takes STRAT to OPS, a space fight takes STRAT or OPS to TAC, a ground fight never pulls TAC up, and a space fight ending mid ground battle lands on OPS. When the last fight ends (ground fights count 2 sim-days after the last shot) the clock returns to STRAT whatever pace it was on; a pace the player picks with no fight going is left alone. The cheat console (`DebugConsole`, backtick or the Sandbox panel's button, open state in `state/debugConsoleStore.ts`) is mounted in dev builds and in the sandbox in ANY build, so it ships in production but only renders in the sandbox. Moons are treated like planets for panels and the Outliner (tabbed inspect panel, Colonies list, own Armies row).

## Working style
- User gives real-time steering mid-task; treat short corrections as authoritative constraints.
- Ask (AskUserQuestion) before large architectural commitments; use plan mode for big features.
- No invented data/mechanics for systems that don't exist yet. Report test/balance findings honestly, including "no bug found".
- Live browser verification for anything UI-observable.

- **HUD notes:** selecting a ship never changes the view type (lock-on just pans: `InterstellarScene` pans to a nested ship's star). Cargo ships/construction ships have "Refill at nearest station" (`scene/refill.ts`: flies to the nearest world the nation owns, loads on arrival). Map Modes live in the bottom bar's right corner (`components/MapModesButton.tsx`, with the "Border & nation names" toggle in `mapModeStore.showNationNames`; off, hovering a border shows its owner via `state/hoverTipStore` + `components/HoverTip`). The bottom bar is a fixed 54px flex row (comms | time controls | action buttons | map modes + location), never absolutely centred (it used to overlap at narrow widths). Text selection is off app-wide except in inputs (`index.css`).
